# Open Chess Review：青鸟美学与完整棋类平台的整体重设计

日期：2026-09-23。状态：**设计方案 + 可交互布局原型，尚未替换生产界面**。

## 0. 结论与交付边界

用户指出的问题成立：此前几批主要调整局部间距、装饰、标题和转场，没有解决统一的页面结构。继续给每个页面添加羽毛、淡色边框、衬线标题，无法把它们变成一个完整的平台。

本轮采用新的设计方向：**以清透、精确的棋类工作台为主体，以水彩和自然色彩建立品牌情绪。** 首页可以有叙事性，工作台需要稳定，数据页需要秩序。三者共享排版尺度、边界、导航与状态语言。

交付：

- 本文：逐页问题、目标结构、交互、实现位置、验收条件与迁移顺序。
- [14 页可交互设计预览](../prototypes/bluebird-platform-v4/index.html)：书桌、导入、棋谱库、引导复盘、着法、讲解、引擎、笔记、完成、练习、成长、设置、帮助、分享。
- 一张新生成的水彩蓝鸟插画方向样稿；不是电影官方素材，也不是最终品牌标志。

原型中所有数字、棋手、统计、进度均是示例。棋盘仅显示合法的 `1.e4` 后位置，不运行引擎，不提供真实分析、走棋、保存、同步或导出。搜索示例棋谱、页面切换、展开内容和会话内笔记演示可操作。正式功能仍在原应用中。

本方案拟替代此前“保持房间背景和左轨、持续局部修补”的设计路线。**现行生产视觉合同尚未整体改写**：正式实施新外壳时，应同步修订 `windowlight-contract.md`、`windowlight-bluebird-v2.md` 和 `ui-spec.md`。不要把提案中的目标当作现有行为。

## 1. 参考研究：学什么，如何转化

### 1.1 Kylin：整体性来自重复的规则

直接检查了 [Kylin 首页](https://projectkylin.org.cn/) 与 [功能区](https://projectkylin.org.cn/system)。其黑底、荧光色、大号排字不是我们应该搬过来的皮肤。值得学习的是：

1. 顶部导航、章节侧栏、内容边界形成固定的坐标。
2. 标题、编号、正文、分隔线有统一比例。
3. 首页的个性延续到功能目录，没有进入功能页就换一套网站。
4. 目录的重复单元有共同边界，页面有明确的重心和结束位置。
5. 一个区域有一个显著的任务，不把所有功能同时放在第一屏。

转化：全站使用统一顶部导航与内容宽度；以章节编号、小型英文标注和细线建立秩序。不要复制启动等待、黑色战术终端风格或大面积装饰动画。这里评估的是视觉组织，不是宣称它的功能完成度。

### 1.2 《リズと青い鳥》：不仅是米白加灰蓝

检查了[电影官网](https://liz-bluebird.com/)与[官方导演访谈](https://liz-bluebird.com/interview/)。官网同时包含白底、蓝色导航、粉色标题与鲜活的水彩绿；绘本部分与现实校园部分也并非同一种视觉材质。导演访谈强调细致线条、微妙表达，以及近似隔着玻璃观看的透明感。

因此，“空气感”的界面转译应包括：

- 高明度底色与少量有生命力的颜色，而非全面灰化。
- 细线、轻材质、明确的前后层次，而非到处半透明磨砂。
- 自然、有机且不完全机械对称的插画，与精确的操作网格共存。
- 克制的时间感：内容轻轻进入，任务立刻可用；不强迫等待故事演完。
- 通过留白让内容呼吸，而非通过巨大空白弥补内容没有组织。

这些是根据来源作出的设计转译，不是官方发布的 UI 规范。本文配色值和动效时长均为本项目提案。

### 1.3 截图中的蓝鸟为什么失败

当前 `bluebird-motif.tsx` 的飞鸟以尖锐的几何切片表达翅膀、身体与尾羽。视觉上更接近图标或标志，缺少羽毛、身体体积、自然姿态与水彩边缘。放在完成页标题前又获得过高的视觉权重，用户先看到装饰，再看到复盘结果。

修复：

- 退出完成页的大型几何飞鸟；完成感来自结果与下一步，而非强制播放品牌图形。
- 不把这张新水彩图塞到每个页面。首页使用横幅，初次使用可用局部插画；引擎、着法、笔记不摆鸟。
- 品牌标识、动作图标、棋步质量图标、情绪插画分开管理。生成图不能承担 16px 功能图标职责。
- 羽毛不再作为所有标题前的默认装饰。确需使用时必须有清晰构图作用。
- 目前新图是较自然主义的水彩鸟，尚不是电影绘本造型的精确还原。最终插画应进一步确定线条、鸟形和植物语言，并统一一组资产，不能承诺一张生成图已经解决品牌系统。

## 2. 现有平台的结构性问题

| 问题 | 用户实际感受 | 根因 | 修复方向 |
|---|---|---|---|
| 左短右长 | 棋盘旁是一条无限向下的内容墙 | 同时展开结果、证据、设置、统计；两栏独立增长 | 棋盘与当前任务共用工作区，详情分层，整局图表下移全宽 |
| 页面像拼接 | 换页后重心、宽度、标题位置都变 | 每个路由自行组织外壳与卡片 | 统一外壳 + 三种明确模板 |
| 房间图片压住内容 | 文字像浮在壁纸上 | 工具页未提供稳定阅读表面 | 工具页取消照片壁纸，内容用实底 |
| 每页都在介绍自己 | 页面头大、进入操作慢 | 宣传页文案进入工具页 | 品牌叙事集中首页，功能页短标题与状态 |
| 装饰反复出现 | 羽毛、鸟、英文小字像贴纸 | 缺少使用场景和权重限制 | 插画限场景，动作图标保持统一尺寸 |
| Review 与 Library 重叠 | 不知道去哪里找棋局 | 导航按历史组件而非用户任务组织 | 一个棋谱库，多个筛选视图；保留旧路由兼容 |
| 空态特别空 | 没有数据就只剩大片背景 | 用有数据页面的空间容纳一句无数据说明 | 空态有明确任务、示例与下一步，适当收缩布局 |
| 转场仍不连贯 | 每切一个标签像换了网页 | 切换范围过大、元素位置变化 | 工作台保留棋盘，仅换右侧内容；页面转场不遮挡交互 |

**“对称”不是所有列强行各占 50%。** 需要的是共同的上下边界、标题基线、列间距和视觉重量。棋盘与讲解可以等权；目录与正文可以不等宽。不能用空卡片、硬塞高度、巨大留白或裁掉文本制造假平衡。

## 3. 新的信息架构与页面模板

### 3.1 全局导航

主导航：书桌 / 棋谱库 / 练习 / 成长。导入为主操作；设置、帮助为工具入口。

- `/history` 是棋谱库；`/review` 作为“已分析”入口保留，可映射到同一列表视图。
- 单局内局部导航：复盘 / 着法 / 讲解 / 引擎 / 笔记。
- “成长”对应现有 `/stats`，只改变表达，不增加不存在的等级分系统。
- 现阶段没有在线对战、云账号、匹配、赛事系统。不要为了像 Chess.com 而展示无法使用的入口。
- 英文版/中文版应一致，不把全站永久混合为中文任务名加英文长段说明。原型用中文方便审阅，少量英文只作品牌辅助。

### 3.2 三种模板

| 模板 | 页面 | 结构 | 滚动责任 |
|---|---|---|---|
| 总览 | 书桌、棋谱库、练习、成长 | 统一标题 → 主要任务 → 横向分区 | 页面滚动，避免嵌套小滚动框 |
| 棋盘工作台 | 复盘、着法、讲解、引擎、局面笔记、练习中 | 棋局身份 → 模式标签 → 棋盘 + 当前任务 | 桌面棋盘稳定，长着法/候选区可独立滚动；手机页面流动 |
| 资料/配置 | 导入、设置、帮助、分享检查 | 紧凑标题 → 局部目录 + 单一内容区 | 页面滚动；文章不限制成小窗口 |

布局提案：

- 最大内容宽 1240px；常规侧边距 32px，手机 16px。
- 工作台最大宽 1100px，列间距 24–32px；棋盘依据可用宽高缩放。
- >=1100px：双栏工作台；600–1099px 根据可用棋盘尺寸决定双栏或提前堆叠，不能只按一个设备名判断。
- <=600px：单列，棋局标题压缩，棋盘优先，模式栏横向可达，正文在下方。无覆盖棋盘的固定底栏。
- 正式工作台的可用高度按视口减去真实头部高度；低高度屏幕允许页面滚动，不能缩到棋子无法操作。
- 页面结束位置明确，页脚轻，不把空白强行拉满多屏。

## 4. 逐页设计与修复规格

以下将“本轮真实渲染观察”“已有验收观察”“源码检查”与“提案”区别看待。本轮直接查看了现有导入、练习、引擎及参考站；此前同一任务已经检查首页、棋谱库、复盘、完成、统计、设置、笔记的多个尺寸。帮助、分享本轮主要基于源码和路由职责，不声称所有错误状态已实机覆盖。

### 4.1 书桌 `/`

**问题**：示例棋盘、导入、账户、最近记录竞争同一层级，用户进入后不清楚今天先做什么。壁纸承担了过多品牌表达。

**新结构**：一幅横向水彩开场 → “继续复盘 / 今日练习”共同一行 → 最近棋局列表。已有用户主按钮恢复最近真实进度；初次用户变成“导入第一局棋”，次操作为示例棋局。

**实现**：`home-workspace.tsx` 只负责真实数据分流，拆出可复用的 ResumeGame 和 RecentGames 行；不再嵌一整套导入表单。插画有固定尺寸、替代背景色，图片加载不能推挤布局。

**状态/验收**：无历史、已有未分析、已有复盘进度、记录失效分别有正确入口；手机首屏可找到主操作；插画不压住标题。大幅图不做持续漂浮。

### 4.2 导入 `/import`

**问题**：左侧大输入表单、右侧松散账号区；表面材质不一致，内容重心偏斜。输入、同步、已有记录混在一起。

**新结构**：输入来源切换（粘贴 / 文件 / 公开账号）→ 检查 → 开始。内容占一个稳定区域；说明放字段附近，不另起长侧栏。

**实现**：复用现有 `import-desk.tsx` 与 `connected-accounts.tsx` 逻辑，改变组合；保留跨来源草稿，明确多局选择。PGN 进入整局流程，FEN 进入局面分析。文件和同步各自显示自己的进度、取消和错误。

**状态/验收**：空输入、无效文本、多局 PGN、FEN、导入中、同步部分失败、取消后保留输入；主按钮始终对应当前步骤。禁止把 PNG 导出误当图片导入。

### 4.3 棋谱库 `/history` 与复盘入口 `/review`

**问题**：两页职责重复，卡片/列表语言不同；在小屏上操作与长棋手名挤在一起。

**新结构**：一个库；全部 / 待分析 / 已分析 / 有笔记为视图。统一搜索与过滤条，清楚显示当前结果数量和筛选条件。行内信息优先级为棋手、结果、开局、状态、主操作。

**实现**：在 `history-page.tsx` 与 `review-index-page.tsx` 之上共用 LibraryView；保留两条路由兼容，不删除旧地址。过滤参数写入 URL；返回列表保留筛选和滚动。批量操作独立工具条，删除保留原有保护。

**状态/验收**：库空、筛选零结果、分析等待、失败、过期结果、长姓名、100+ 行。手机不压成微型表格；将次要字段放第二行。全局准确率与行内哪一方准确率必须标清。

### 4.4 引导复盘 `/review/[gameId]`

**问题**：棋盘稳定性已改善，但右侧内容层级和页面外壳仍松散；开始、关键时刻、练习、完成像多个布局。

**新结构**：固定棋局身份和模式栏；同一棋盘区域配一张当前任务面板。开始态展示分析状态或概览；每个关键时刻只呈现结论、核心证据、下一步。深入证据可展开。

**实现**：`review-shell.tsx` 提供稳定框架，状态内容由 `review-route-panels.tsx` 与 review 子组件插槽提供。保留键盘导航、进度、探索分支、返回主线、取消分析。整局图表放工作台下的全宽区域，避免右列无限增长。

**状态/验收**：未分析、部分完成、可用结果、关键时刻、探索、原位练习、重试、失效棋局。切换模式棋盘的尺寸和坐标不跳；前进后退不丢进度；不为了动效重新挂载引擎。

### 4.5 着法 `/moves`

**问题**：大量着法和补充资料可能让右栏变成长文章；若使用摘要卡片密度，检索效率低。

**新结构**：左棋盘，右为紧凑棋谱表与变化树。选中着法有行/格底色与非颜色标识；质量图标与简短评价同列，详细解释按选中项展开。

**实现**：复用 canonical SAN、质量和评价数据；不在组件里重算分差。滚动跟随选中着法但不抢走用户主动滚动。分支与主线有明确返回操作。

**验收**：长棋局、多个变化、键盘快速跳转、首末步、黑方视角；点击与棋盘状态一致。图标不能代替可读标签。

### 4.6 讲解 `/coach`

**问题**：客观结论、人类概率和 AI 长文本容易挤成同一条解释流，且长度不可控。

**新结构**：当前着法 / 整局主题分层；第一屏包含一句结论与短证据。Stockfish、Maia、AI 教练有各自来源标签，长文为段落和展开区。

**实现**：先显示确定性内容；AI 按需请求，保留取消和失败重试。服务未配置时解释缺少什么并给配置入口，不把页面留空。不将生成结果覆盖引擎结论。

**验收**：无 Maia、无 LLM、流式生成、失败、长解释、非法生成着法。生成文本需验证沿用现有实现，UI 不另建事实层。

### 4.7 引擎 `/engine`

**已观察问题**：控制参数、引擎版本、缓存、阶段数据、PV 堆在照片背景上；页面头仍像引导式复盘，工具身份不清。

**新结构**：工作台右侧顶部一条控制行；下方候选变化表；开局数据库和残局库按需展开。参数、运行状态、结果严格分开。高级元数据进入“分析信息”。

**实现**：复用现有 Stockfish 生命周期，布局切换不能启动重复实例。白方 POV、mate、深度、MultiPV 和来源保持真实。FEN 局面没有整局准确率时不造空统计。

**验收**：启动中、计算中、停止、缓存命中、断连、无合法步、将死、残局库不适用。长 PV 可换行，棋盘不被撑窄。

### 4.8 笔记 `/notebook`

**问题**：局面、编辑、保存反馈、已存条目容易纵向叠加；旧纸张装饰与其他工作区不一致。

**新结构**：左棋盘右编辑器，当前局面身份固定。历史笔记通过紧凑列表/抽屉选择；编辑器是主要区域。保存反馈在按钮附近，不需要羽毛动画。

**实现**：复用持久化、书签和变化保存；自动/手动保存行为以现有契约为准。切换局面处理未保存状态，不能因换页默默丢稿。

**验收**：空、长文、保存成功/失败、修改后切换、失效局面、移动端键盘打开。只有真实存储成功才显示“已保存”。原型的内存保存明确不等于正式保存。

### 4.9 复盘完成（复盘状态）

**问题**：用户截图中的巨大几何鸟抢走结果焦点。左右摘要/动作的密度差异进一步显得失衡。

**新结构**：简短完成标题 → 明确范围的结果带 → 一项主要收获与下一步。全宽排列，避免一侧只有鸟另一侧很长。

**实现**：移除大型 flight 装饰；读完与提前查看总结使用不同标题。准确率来自既有算法，已阅读/已练习/已掌握不混称完成。

**验收**：真正读完、提前总结、没有关键时刻、只有 FEN、数据不完整。关闭动画也不能失去完成反馈。

### 4.10 练习 `/training` 与进行中练习

**已观察问题**：大幅空卡片、账号/历史分析入口和背景空间没有形成行动顺序。研究型多标签统计与“今天练什么”争夺首页。

**新结构**：今日任务为唯一第一主区；下方训练计划与来源棋局。开局/中局/残局/错误/覆盖率等研究维度收进二级“训练洞察”，不把九个标签放成平铺入口墙。进行中复用棋盘工作台，答案隐藏。

**实现**：`advanced-study-page.tsx` 拆分任务入口和洞察内容组合，保留训练调度与掌握算法。`retro-practice.tsx` 对齐工作台，不修改间隔复习语义。

**验收**：未导入、已同步未分析、已分析无任务、有到期任务、正确/错误尝试、主动看答案、当天重复、跨天复习。不能把有 100 局同步记录误说成已有 100 局训练分析。

### 4.11 成长 `/stats`

**问题**：不同数据集合的数字视觉上并列，容易误认为同一分母；图表堆叠可能继续产生左右失衡。

**新结构**：全页统一范围条 → 三个核心数字 → 按主题全宽分区或同高度图表行。图表有问题句，例如“最近复盘是否持续”，而非单纯炫耀指标。

**实现**：明示浏览器库、账号同步、已分析子集的区别。过滤变化同步更新所有相关指标，暂无数据用解释而不是零准确率。图表支持文本摘要。

**验收**：空库、部分分析、多个账号、不同时间范围、少样本；展示统计口径。不会引入自创“官方等级分”。

### 4.12 设置 `/settings`

**问题**：太多配置整页堆积；固定目录只能改善跳转，不能减少阅读负担。

**新结构**：类别目录 + 当前类别。棋盘显示、引擎、人类预测与教练、连接账号、本地数据。每类一张连续表单，帮助在字段附近。

**实现**：保留深链接和浏览器返回；实时保存字段有状态，需确认的操作有明确边界。密钥保持既有敏感数据处理，模型缺失是设置状态，不自动下载。

**验收**：错误 URL、未连接、模型缺失、保存失败、备份/恢复、移动端目录；破坏性操作在数据类别中独立分区。

### 4.13 帮助 `/help`

**问题**：作为长文，其阅读规律不同于棋盘页，不应套宽工作台或壁纸。

**新结构**：短目录 + 60–75 字符阅读宽度正文。第一步指南、能力边界、快捷键、数据与隐私、本地模式各自有锚点。

**实现**：保留现有准确的 Browser Core / Enhanced Local 内容；帮助链接直达对应设置和操作。键盘表格手机可读。

**验收**：长文滚动、锚点定位、200% 缩放、键盘导航；不把无云同步包装成账号功能。

### 4.14 分享 `/share` 与导出

**问题**：分享是输入边界，不应直接呈现“已保存”的成功界面；导出则应延续正式品牌规范。

**新结构**：读取 → 检查 → 预览 → 用户保存。损坏链接有解释与替代入口。图片导出预览使用棋局身份、棋盘和必要结果，不带站点导航或大幅壁纸。

**实现**：复用既有分享验证及导出逻辑；输入验证错误与存储失败区分。图像里的质量图标使用同一 canonical 映射。

**验收**：有效、缺失、损坏、不支持版本、重复导入、导出失败。新水彩图不得抢占棋盘分辨率。

### 4.15 内部设计页、404 与加载状态

`/design/pieces`、`/design/quality-icons` 是验收工具，不进入消费者主导航。404 提供返回棋谱库；丢失本地棋谱解释“当前浏览器找不到数据”；加载骨架与最终布局共边界；引擎计算进度不伪造百分比。离线说明哪些浏览器能力仍可用，不能把服务缺失等同于全站不可用。

## 5. 视觉系统

### 5.1 色彩提案（并非官方取色）

| 角色 | 值 | 用途 |
|---|---|---|
| 冷白纸面 | `#F8FAF7` | 全站底色 |
| 内容白 | `#FFFFFF` | 编辑、阅读、工具表面 |
| 墨蓝 | `#29444E` | 正文与主标题 |
| 次级文字 | `#597078` | 辅助说明，实施时逐组合测对比度 |
| 青鸟蓝 | `#3E708C` | 主操作、选中状态、品牌细节 |
| 薄雾蓝 | `#E9F1F3` | 选中背景与轻提示 |
| 青瓷绿 | `#A4BCAE` | 棋盘与自然色辅助 |
| 淡玫瑰 | `#AD737F` | 小范围装饰，不替代错误语义 |
| 结构细线 | `#D8E2DF` | 分区，必要控件边界另行确保可辨 |

着法质量、警告、错误、成功使用现有语义映射，不为了全站浅色而消除可辨性。标签兼具形状/文字，不能只依赖色觉。

### 5.2 字体与组件

- 首页情绪标题使用衬线；工作台标题与正文使用清晰无衬线。
- 数字使用 tabular-nums；棋谱与坐标维持稳定宽度。
- 文字层级建议 12/14/16/24/32/48px，手机降低标题而非缩小正文。
- 常规圆角 3–6px，避免每个模块都是大圆角浮岛。
- 阴影只为真正浮层提供层级；静态分区依赖网格和线条。
- 按钮触控目标至少 44px；主操作每区一个；不要把普通说明做成貌似可点击的标签。
- 正文不可直接压在照片细节上。插画区域有文字安全区、固定比例与加载占位。
- 原型复用了现有 Feather Porcelain 棋子，用于验证结构；这不代表棋子资产已重新设计或用户已认可。

## 6. 动效与跳转规格

| 场景 | 提案 | 不能发生 |
|---|---|---|
| 主路由切换 | 新内容 160–220ms 淡入，最多位移 4px | 整屏滑动、等待开场、阻塞点击 |
| 棋局模式切换 | 棋盘持续存在，仅右面板 120–180ms 切换 | 棋盘重挂载、跳尺寸、重新跑分析 |
| 棋子移动 | 沿用棋盘已有可配置动画 | 品牌动效覆盖棋盘反馈 |
| 展开证据 | 短过渡或直接展开，保留滚动位置 | 展开后标题移出视口、内容被硬高度裁掉 |
| 保存 | 按钮旁出现短文本状态 | 每次弹大弹窗或让鸟飞过屏幕 |
| 完成 | 摘要出现、下一步立即可用 | 强制庆祝动画、必须等待结束 |
| 减少动态 | 禁用位移/装饰，仅即时状态变化 | 因无动画而漏掉反馈 |

前进/后退恢复路由状态；新页焦点移到主标题或主内容，页内模式切换不抢走键盘焦点。动效只用 transform/opacity 等轻量属性，避免持续全屏滤镜。

## 7. 工程落地顺序与改动边界

### 阶段 A：统一外壳与一条完整用户路径

1. 更新视觉合同，明确新模板替代旧壁纸和左轨要求。
2. 建立 `PageHeader`、`OverviewLayout`、`DocumentLayout`、`ReviewWorkbench` 等组合组件；不要一个万能组件塞几十个布尔参数。
3. 改 `app-shell.tsx` 与 tokens/chrome，建立顶部导航及响应式。
4. 接入首页、导入、棋谱库真实数据，完整跑通“导入 → 分析 → 回到棋谱库”。
5. 移除完成页大型 flight；图片只在首页加载。旧样式在无消费者后删除，避免一层层覆盖。

验收门槛：真实数据可用；移动端导航可达；旧链接兼容；未修改存储和算法语义。

### 阶段 B：复盘工作台五模式

1. 统一头部、棋盘、模式栏和当前任务表面。
2. 按复盘 → 着法 → 引擎 → 讲解 → 笔记迁移。
3. 对齐开始、关键时刻、练习、完成状态。
4. 引擎/开局/残局服务生命周期与 UI 组件分离；长列表管理滚动。

验收门槛：同局模式切换不丢进度、不重新分析、不丢草稿；320/390/768/1024/1440 宽及低高度屏幕没有操作遮挡。

### 阶段 C：练习、成长与资料页

1. 练习入口聚焦今日任务，研究维度变为二级内容。
2. 统计统一数据范围和缺失状态。
3. 设置类别化、帮助阅读化、分享状态化。
4. 统一导出视觉与无障碍细节。

验收门槛：真实空态和异常态可用；保存/备份/导出不是假按钮；功能范围如实表达。

### 阶段 D：艺术资产与最终打磨

统一插画、品牌标识、图标尺度；对照官网而非凭记忆继续画。按实际页面验收鸟的大小、裁切、与文字的距离。性能测试后再决定是否需要更多资源，优先少而精。该阶段不应再次推翻已经稳定的任务布局。
