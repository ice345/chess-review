# 蓝鸟棋室：平台布局、视觉与转场改进方案

日期：2026-09-22  
状态：设计提案，尚未实施；不代表已经通过视觉验收。  
检查基线：`62ecc44` 加当前工作区修改。当前有大量进行中的 UI 修改，本次保留它们，只新增本文件。

## 1. 结论

现在的平台已经有统一的窗光、暖纸、冷蓝棋盘和章节标题，不能说没有风格。但它的辨识度仍较多依赖整张房间背景。把背景拿掉，许多页面仍是相似的侧栏、圆角纸卡和表单；蓝鸟没有成为贯穿任务的视觉语言，转场也没有充分表达操作前后的关系。

建议下一版以 **“蓝鸟棋室：窗边的一本棋谱”** 为方向：真实的棋盘是空间中的稳定核心，复盘像展开棋谱，证据像页边批注，练习像暂时盖住答案，保存像夹入一枚羽毛书签。蓝鸟与羽毛直接出现，并承担清楚的角色。

优先级：**稳定棋盘与信息布局 → 建立蓝鸟与纸页语言 → 编排关键转场 → 扩展到所有页面。** 只增加漂浮羽毛或更长淡入，解决不了当前问题。

这里的“蓝鸟棋室”是美术方向工作名，不要求替换产品名称或现有 logo。

## 3. 麒麟值得学习的地方

| 观察 | 对我们有用的转译 |
| --- | --- |
| 黑、荧黄、细网格、编号和压缩字体反复出现 | 我们也需要反复出现的蓝鸟轮廓、纸边、蓝色书签、窗框比例 |
| 大标题与细小档案标签形成明确对比 | 叙事标题与工具文字分工，避免所有区域都同样轻、同样淡 |
| 四章节始终有位置和进度 | 让导入、理解、练习、保存有可感知的进程，但主要导航仍使用明确功能名称 |
| 转场与它的几何块面语言一致 | 我们采用纸页接续、窗边掠影、细线延展；不复制硬切黑块和荧光色 |
| 首屏用棋盘作为视觉中心 | 我们的品牌页仍应让真实棋盘、实际局面成为中心 |

不建议把工作区改成滚轮翻屏。棋谱、变例与证据需要正常滚动、选择和键盘操作；品牌入口可以有章节感，持续工作的复盘界面应保持直接。

## 5. 美术方案：让蓝鸟成为界面的一部分

### 5.1 两种场景，一套操作系统

**窗边 / 现实层**用于复盘、分析、设置：暖白纸、冷窗光、清晰深蓝墨色、稳定棋盘、少量木色。强调观察和思考。

**绘本 / 叙事层**用于首页空白区、空状态、练习结束：水彩蓝鸟、淡绿枝叶、微粉小花、较自由的留白。强调好奇与回顾。

两者用同一字号体系、线条、按钮和语义连接。不要每个页面都换一张完全不同的全屏插画。

### 5.2 母题分工

| 元素 | 位置和作用 | 表现形式 |
| --- | --- | --- |
| 蓝鸟 | 首页窗边、章节页边、复盘完成 | 一只主鸟为主；统一头部、喙、翼和尾部轮廓；静止姿态优先 |
| 羽毛 | 已收藏局面/笔记书签、保存结果 | 小尺度简化轮廓搭配“已保存”等文字；不能替代 Brilliant 或其他质量标记 |
| 窗框 | 全站构图的边界与留白 | 很淡的纵横结构，落在内容边界而非穿过正文 |
| 纸页 | 复盘内容、证据、练习题 | 统一纸色、细边、轻阴影；不做每张卡都翘角的装饰 |
| 谱线感 | 章节进度、已看关键时刻 | 简单细线与节点；每个节点对应真实步骤，不摆无意义的乐谱 |
| 枝叶/水彩 | 首页与空状态边缘 | 集中一处，保留安静区域，不铺满表单 |

可以更直接使用官方蓝鸟、羽毛和绘本视觉作参考，甚至采用选定的官方图像作为私用主题素材。具体资产应逐张确定来源、裁切和用途，不能把任意素材都称作“官方蓝鸟”。背景、主鸟、UI 小图标要分别制作，避免从复杂宣传图硬抠缩成模糊图标。

建议资产清单：`bluebird-perched`、`bluebird-flight`、`feather-bookmark`、`window-wash`、`storybook-branch`，以及各自浅底/深墨单色版本。名称是拟新增资源，不表示仓库已有。

### 5.3 建议调色起点

| 角色 | 建议色 | 用途 |
| --- | --- | --- |
| 纸白 | `#FAF9F2` | 大面积承载面 |
| 冷窗光 | `#E7F1F4` | 空间底色 |
| 玻璃青 | `#C7DAD8` | 环境分界、小色块 |
| 蓝鸟蓝 | `#5E8FB5` | 插画与装饰，不直接假定适合白字按钮 |
| 深蓝墨 | `#294653` | 正文、主要图标 |
| 操作蓝 | 延用现有 `#54708F` 起步 | 主按钮与焦点，重新合成测试后再调整 |
| 粉色 | `#D6A1B9` | 少量叙事强调 |
| 叶绿 | `#AEC5AC` | 绘本环境 |

“空气感”来自有亮暗层次的空白、清楚的前景和较远的环境，不等于把所有文字、边框和棋子都降低透明度。正文、棋子和状态仍要足够实。

## 6. 页面布局方案

### 6.1 首页：进入棋室

桌面建议结构：

```text
固定导航 │ 一个短叙事标题                     窗边蓝鸟 / 留白
         │ 真实棋盘或最近局面          继续上次复盘（主行动）
         │                             对局、进度、关键时刻
         │                             导入新棋谱（次行动）
         │ 最近棋谱的少量横线条目      练习入口
```

- 有可继续对局：默认选最近真实对局，显示双方、上次停留位置和继续按钮。
- 无对局：右侧变为导入入口；提供示例棋局；示例清楚标注。
- PGN 编辑器在选定导入后展开，避免初始大空表单占据整个首页。
- 仍允许快速粘贴和打开文件；不要增加必须经过的营销介绍或启动影片。
- 手动摆棋有明确入口，进入后才强调棋盘交互和重置/撤销。

### 6.2 复盘：一本展开的棋谱

```text
固定导航 │ 对局标题                  Review / Moves / Study / Analysis
         │ 稳定棋盘                  当前任务标题
         │ 棋手信息与评价条            一个关键解释 / 一个主按钮
         │                           已看关键时刻进度
         │ 走子控制                  引擎证据 / 相邻走子 / 总结
```

- 不靠不停缩小字来适配窄屏；空间不足先把次级证据竖排，再重排布局。
- 把“棋手行、棋盘、走子控制”作为稳定单元，标题长度不改变它的位置。
- 蓝鸟只出现在页边或章节进度端点；不进入 64 格，不遮挡评价条。
- 分清事实来源：Stockfish 事实、Maia 人类倾向、Coach 解释各有文字标签。主题改造不改变分析语义。

### 6.3 练习：把答案暂时盖住

- 棋盘继续保持同一位置和比例，右侧从解释页变为问题页。
- 必要指令立刻可见，答案和引擎线在揭晓前隐藏；不能仅用低 opacity 隐藏可读答案。
- 提交后依次呈现结果、关键原因、可执行的下一步；下一题始终在稳定位置。
- 羽毛只用于“保存这道题/这条笔记”，不奖励每一步普通操作。

### 6.4 Library、Stats、Settings

- Library：使用现有 folio 横线列表基础；羽毛表示实际收藏，保留筛选、排序、状态文字。
- Stats：统计图表占主位，叙事标题缩小；不为主题把刻度和图例淡到看不见。
- Settings：清楚的设置分组、保存反馈和连接状态；蓝鸟只在页头，避免每个开关都配装饰。
- 统一空、加载、失败、离线状态。失败显示原因与恢复操作，不能只显示一只忧伤的鸟。

### 6.5 手机与小屏

- 保留现有 1080px 以下导航抽屉的基础，先验证，不盲目新增另一套导航。
- 手机首页顺序：继续/导入 → 局面预览 → 最近棋谱；主操作不被大插画推走。
- 复盘单列：紧凑对局标题 → 棋盘 → 固定位置的走子操作 → 当前任务 → 可展开证据。
- 装饰裁切为边缘的一小段；320px 宽和字体放大时可自动去掉装饰。
- 不在手机使用整屏翻页、视差或横向拽纸。触摸目标建议至少 44px。

## 7. 转场分镜与行为规范

以下都是建议值，需在真实页面和分析负载下调试。

| 触发 | 分镜 | 预算 | 中断 / reduced motion |
| --- | --- | --- | --- |
| 导航切页 | 导航状态立即变化；旧内容淡出，新内容沿纸页边缘短距离出现；环境不动 | 180–260ms | 连续点击以最后目的地为准；减少动态时直接替换或 ≤100ms 淡入 |
| 开始 → 关键时刻 | 棋盘框不动；局面与标题同步更新；右侧解释出现；进度节点着色 | 180–240ms | 不等待动画才允许下一步；可取消旧过渡 |
| 关键时刻 → 练习 | 右侧证据退出；题目纸出现；题目与合法走子状态同时就绪 | 200–280ms | 不让棋盘提前接受属于旧题的输入；慢加载显示真实准备状态 |
| 展开证据 | 箭头转动，证据就地展开；用户触发点保持可见 | 140–180ms | 减少动态直接展开；避免改变棋盘位置 |
| 保存成功 | 图标从空书签到羽毛书签，纸边出现短暂淡蓝色 | 180–260ms | 以持久化成功为前提；文字状态不依赖动画 |
| 完成复盘 | 结果先出现，鸟沿纸面外缘掠过一次后离开 | 450–650ms，低频 | 这是拟新增的例外，不是现行 Tier B；不阻塞按钮，可关闭 |

不要制造虚假 0–100% 加载进度；分析进度来自实际阶段或已完成局面数。蓝鸟可静止陪伴加载，但它的飞行距离不能假装剩余计算时间。

默认不播放背景音乐。若以后增加声音，提供明确开关和音量，初始静音；提示音不承担唯一反馈。

## 8. 工程落实

### A. 先修布局，保留现有主题

- `apps/web/src/app/styles/review-shell.css`、`review-workspace.css`、`chrome.css`：固定同一断点下的棋盘锚点，解开页头与棋盘的高度耦合。
- `apps/web/src/app/styles/review-panels.css`：证据窄列改单列，移除核心动作文字的过度省略。
- `apps/web/src/components/home-workspace.tsx`：区分继续对局与首次导入状态，保留真实数据。
- 验收 Home、Review Start、Key Moment、Practice 四屏之后再扩展。

### B. 制作可复用的主题语言

- 在 `packages/ui` 增加鸟/羽毛资产和薄包装组件，装饰默认 `aria-hidden`、`pointer-events:none`。
- 资产通过用途选择，不在各路由复制 SVG/path 或散落绝对定位。
- 先出一套桌面和手机静态构图，再实现。检查缩小后的形状，避免大图漂亮、小图不可辨。
- 在 tokens 中区分装饰蓝、操作蓝与语义色。保留现有 quality icon 的分类含义。

### C. 编排转场

## 9. 验收清单

1. 画面：1440×900、1280×720、1024×768、390×844、320px 宽；覆盖长棋手名、空库、载入中、失败和完成状态。
2. 连贯性：同局开始/关键时刻/练习切换，棋盘框不跳；快速连续点下一步不串状态；浏览器后退恢复对局与棋步。
3. 易读性：重要动作不只剩首字母；白棋在两色格上都可辨；按实际背景测量正文和焦点对比度。
4. 可访问性：键盘完成导入、开始复盘、看证据、进入练习；隐藏答案不可被读屏或 Tab 提前访问；reduced motion 下任务完整。
5. 性能：在 Stockfish 分析中检查掉帧和输入响应；新增装饰不增加 engine 实例；不加载未使用的大型插画。
6. 业务：动画不改变分析结果，不把保存失败画成成功；刷新不依赖播放过动画才能恢复。
7. 风格：关闭背景仍看得出蓝鸟棋室；打开背景后文字和棋盘仍先被看见；全站只有一套鸟形、线条和纸面规则。

本次只交付调查和提案，没有运行构建或算法测试，也没有宣称以上验收项已经通过。后续实施应先检查仓库实际脚本，按改动范围执行相关测试、typecheck、lint、build，并用真实渲染验收；截图基线更新本身不算设计验收。
