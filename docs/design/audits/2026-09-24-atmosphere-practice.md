# Bluebird：实页审计、Practice 修复与下一阶段设计

日期：2026-09-24。范围：当前本地生产代码的开发渲染、已有浏览器数据、官方视觉参考。
状态：本轮完成有限修复；全站艺术方向及训练闭环为后续实施规格，不代表已经全部实现。

## 1. 结论

当前系统已经有一致的字体、棋子和纸面语言，但“统一”尚未转化成鲜明的作品气质。
最大缺口是**空间组织和交互叙事**：许多页面采用同一种浅底、标题、横线、纵向内容，
进入不同任务时场景没有发生足够明确的变化。首页蓝鸟更接近自然水彩插画，单靠它不能
建立与电影的直接联想。继续添加小鸟、英文乐章标签和羽毛按钮不能解决这个问题。

Practice 还有独立的业务问题：队列复习和棋盘答题实际上是两套流程。
原先队列链接打开错误着法之后的局面，而且可在答案可见时自行申报“我会了”。
这使界面承诺的“找回错过的着法”与实际行为不一致。

## 3. 为什么还不像两部作品

| 缺口 | 当前表现 | 改进方向 |
| --- | --- | --- |
| 色彩关系太单一 | 灰蓝绿承担背景、按钮、边界；粉与金几乎只在小字里 | 大面积清白，局部窗蓝；玫瑰粉作为童话边界，铜管暖光作为练习/完成节点 |
| 没有空间距离 | 内容几乎都处于同一平面 | 环境边缘、内容纸面、棋盘三个层级；靠裁切、留白和局部光差，不靠玻璃模糊 |
| 图像只在首页出现 | 一张自然蓝鸟图难以表达学校、合奏、距离 | 首页建立“窗内学习/窗外童话”的构图；工具页只延续同一裁切、材料和边界 |
| 章节只是标签 | MOVEMENT 文案未绑定任务进程 | 章节进度来自导入、观察、尝试、保存、再访的真实状态 |
| 页面节奏相同 | 标题后连续横线，长度由内容决定 | 首页序曲、复盘工作台、练习排练页、棋谱节目单、统计成长档案分别设计 |
| 动效缺少因果 | 页面淡入比任务状态更醒目 | 错误前局面→选择→验证→对照→收束，每一步状态变化可读、可跳过 |

“空气感”不能靠降低所有文字和棋子对比度取得。主文字、棋盘、焦点仍需清楚；
柔和的颜色应发生在背景和边缘。

## 4. 全站设计方案

### A. 首页：窗内与窗外

- 保留一处主插画，停止扩散低质量小鸟图标。
- 下一版素材以白色窗框/窗边桌面与蓝绿水彩外景建立明确前后关系；需要看完整构图后再替换当前图。
- 图片与主要任务共享一个构图，最近对局以真正的棋局信息和继续入口进入“窗内”。
- 最近任务、到期练习、笔记三者按真实数据择一为主；未分析局不伪称可继续某个已保存的 ply。
- 首页下半段做三段不同密度的序列，而非均匀卡片墙：今日一局→近期节目单→可选自由棋盘。

### B. Review：对话式工作台

- 保留当前棋盘左/任务右的工作结构，棋盘不得为了动画位移。
- Stockfish、Maia、Coach 可以形成“客观依据/人的选择/解释”三个声音，但不能合并成一个分数。
- 一个时刻只出现一个主要问题。答案前隐藏最佳着法、评价箭头、对应走子列表和泄题文字。
- 答案后用明确的“你下了 / 更好的选择”对照，默认从决策前局面出发。
- 完成页呈现一条真实学到的内容和一个下一步，才适合铜管暖色或书签收束。
- 桌面比较两列的顶部、基线和控件位置，允许内容长度不同；不要用巨大空白强行等高。

### C. Practice：排练而非报告

- 架构分为“今日练习 / 已存任务 / 准备数据”。准备数据不能与训练主按钮竞争。
- 今日区显示所选玩家、今天可做数量、预计任务规模；无可靠时长数据则不估计分钟数。
- 空状态应区分：没导入、没分析、没有足够重复弱点、无到期任务、读取失败。
- 只有一局也应能练其错题；至少两局的门槛只限制“反复弱点”结论，不能阻止练习。
- 本轮先采用冷色任务页与暖色方法边栏，调整分析表单；下一批用真实题目预览取代较多说明文字。
- 移动端顺序：玩家→今日任务/开始→题目→结果→可选方法/准备设置。

### D. Library / Saved reviews：可查阅的节目单

- 月份分组已有方向，保留。默认首屏至少露出数条实际对局。
- 收紧标题/总数区；把筛选组织为“来源、状态、结果、时间”明确组，不让一串 All 混淆。
- 补 URL 筛选与返回滚动位置；打开复盘再返回应落回原条目。
- 当前对局的入口、真实分析状态、删除操作视觉分离。不要为对称重复数据。

### E. Stats：成长档案

- Your game 的所选玩家应决定全部玩家指标及分析准备入口。
- 库存指标和棋力成长分成不同区，清楚标注 records、unique games、synced、analyzed 的集合关系。
- 先显示一条可靠观察与可行动的练习入口，再给图表；样本不足明确显示不足。
- 折线、阶段对照、开局谱采用同一冷暖体系；不能因想要音乐感把图表画成难读的装饰谱线。

### F. Import / Settings / Notebook（下一批实页复核）

- Import：一张清楚的输入纸，来源图标保持真正 SVG/image，导入完成自然进入新局。
- Settings：清楚分组与保存反馈，不需要插画；危险操作独立。
- Notebook：可以有最明显的纸页与羽毛书签，但必须关联实际局面和保存状态。
- 可重用特征应来自构图与材料，不必让每页都带一只鸟。

## 5. 动效规格

- 导航切换：160–240ms 的颜色/透明度变化；同一局换 ply 不重播整页动画。
- 解题：保留棋子本身移动；错误反馈、回到起始局面、答案展开各有明确状态，异步引擎期间可取消。
- 笔记保存：短暂的书签反馈，仅在持久化成功后出现。
- 完成：一次安静的段落收束，无循环飞鸟、视差背景或强制片头。
- reduced-motion：移除位移/错开入场，保留文字状态、焦点与进度。
- 性能：一处主页大图，提供尺寸与压缩版本；工具页不要为了环境重新解码整幅插画。

## 6. Practice 正确业务流程

### 坐标契约

`faultPly` / evidence.ply：原错误着法的编号（从 1 起）。
`promptPly = faultPly - 1`：用户决策前棋盘。
`fenBefore`：题目；`fenAfter`：原局走完错误后的结果。
任务 key、保存进度、分类证据必须仍然使用 faultPly，不能一起减一。

正常查看精彩着法可以落在走完之后；不能全局把所有 Review 链接都减一。
本轮仅修复训练与开局问题/阶段错误/Mistakes/Plan 的决策入口，Highlights 保持原语义。

### 两种模式

1. **复习（本轮队列入口）**：决策前→显示原着法→比较客观依据→标记已阅读。
   允许自由浏览，但记为 exposed；不增加独立掌握度。
2. **答题（下一阶段接入队列）**：决策前，答案隐藏→合法走子→确定性引擎评判→反馈→保存。
   复用现有 `use-retrospect` / `startAt(faultPly)`，不要再写第三套判分器。

### 目标状态机

`loading → ready → solving → evaluating → solved/rejected/revealed → saving → saved → next`

- source 缺失/不匹配：阻止答题与写进度，说明如何恢复原局。
- 分析缺失：显式恢复分析，不能要求用户自行声明正确。
- 一次提示、查看解答、跳至后续局面、进入能泄题的模式，均不可再计 unaided。
- rejected 允许重试；是否提示后成功都不能伪装首次独立解答。
- 保存必须绑定 taskId、positionKey、attemptId；快速双击与刷新不能重复增加尝试。
- 先持久化结果，再跳下一题；失败保留当前棋盘和重试入口。
- 跳过与暂停不算已掌握；完成本次 session 不等于全部 mastered。
- due 优先，再未练；未来才到期的题可主动回看，但明确不算今日新任务。
- 复习间隔沿用当前 mastery 模块；本次不改 1/3/7/21 算法及历史数据。

### 必须补齐的闭环

目前棋盘内 RetroPractice 与持久化训练队列尚未接成一条可靠的独立答题流程。
本轮移除答案可见时的“I knew this move / I guessed”，堵住不可靠入口；
因此不能宣称目前队列已经能通过真正答题达到 mastered。
下一批最高优先级是接入真实尝试结果与保存，不是把自评按钮重新放回去。
历史已保存的 unaided 数据不自动抹除，后续应为新记录增加可验证的 attempt 来源。

## 8. 后续实施顺序与验收

### P0：真实答题闭环

先接队列到现有 retrospection，再做持久化 attempt；fixture 覆盖白/黑、首步、升变、
合法非最优、替代正确着、mate、网络/引擎失败、答案暴露、暂停恢复、重复保存。
以真正走棋到下一题的浏览器流程验收，不能只用截图或点击自评。

### P1：平台身份

先确定一张“窗内学习/窗外童话”的完整首页构图，再把边界、白/蓝/粉/铜的关系
落到 Practice 与完成页。Review 保持棋盘对比。不要一口气替换全站所有图标。
每张素材保存原稿、WebP 导出、尺寸、裁切规则和来源；官方参考与交付素材明确区分。
本轮没有新增位图，也没有声称已完成新的插画资产。

### P2：任务连贯性

Library 筛选/返回位置，Stats→单题→练习→Notebook 回路，单局错题无重复弱点也可练。
目前这是最有潜力形成自身特色的功能组合：客观棋力 + 人类选择 + 可复习的个人笔记。
不根据 Kylin 目录的功能数量照搬社区、课程或社交系统。

### 验收标准

- 桌面与 390/320px：无横向溢出；主要动作能找到；键盘焦点完整。
- 决策入口棋盘 FEN 严格等于源着法 fenBefore；原着法与正确着法对照明确。
- 未走棋/已看答案不能记独立掌握；自动化必须验证数据写入结果。
- 不同玩家队列、积压、统计不混用；空/失败/未来到期三类状态分开。
- 视觉在实际浏览器验收，不把更新 screenshot baseline 当成正确证明。
- 每批更新本文件的已实施范围、测试结果与剩余项。
